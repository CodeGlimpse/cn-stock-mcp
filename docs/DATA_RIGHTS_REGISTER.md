## 应由经营者补齐的证据

每条证据填写：权利方、服务/数据类别、条款标题与版本或日期、原始 URL、核对日期、允许用途、禁止用途、缓存/展示要求、适用客户主体、审核人及结论。可以记录权利方书面回复的编号，不归档 Token、完整账号配置或含秘密的工单附件。

以下问题需要在首发前形成结论：所选上游是否允许以当前本地工具方式接入并提供有偿部署支持；客户个人查询的范围是否覆盖；是否允许把结果传给其自用 Codex/模型；需要哪些告知、署名或缓存限制。对托管服务、共享 Token、数据转售、公开展示或批量再分发，应另行取得明确证据后再承诺。

若某来源无法确认用于拟售场景，应选择取得许可、替换来源或缩小交付范围，并重新验收受影响工具。不得仅靠免责声明把未核验权限写成已通过。项目不据此决定报价。

静态路由线索：当前 AKShare provider 使用 tool_trade_date_hist_sina、stock_info_a_code_name、stock_zh_a_spot、stock_zh_a_hist_tx / stock_zh_a_daily 等接口；更广能力还包含同花顺板块接口。此清单来自代码，不能替代上游当前实际请求链和授权审核。验收报告的 provider 名也不足以证明最终数据权利主体。
